1.3 平台侧 2026 变化（最容易被忽略、但影响最大）

流量结构已经换了一套规则。
  • Rufus 已更名 Alexa for Shopping（2026-05）：覆盖约 3 亿活跃客户，带来约 120 亿美元下游交易，使用量同比 +400%。消费者不再输入关键词，而是提问；同一关键词对不同买家返回不同结果 —— 搜索从「关键词匹配」变成「对话意图 + 身份匹配」。
  • Project Amelia：亚马逊卖家侧 AI 助手，能答账号问题、拉经营数据，并正在向「代为执行」演进 —— 我们的 Agent 需要说清与它的差异。
  • 亚马逊原生生成式 AI 已免费覆盖：Listing 与 A+ 文案生成（卖家采纳率约 90%、A+ 可提升销量 8–20%）、AI 素材生成（Creative Studio）、基础关键词建议。
  • 原生 AI 明确不覆盖、需付费工具解决的 5 件事：PPC 出价与调优、品牌与跟卖预警、选品研判、真实单品利润、FBA 费用索赔。
  • AI 内容合规披露新规：AI 生成的人物图需元数据披露，短视频平台同步要求 AIGC 标注。

最后一条里那 5 件事，正好构成我们补能力的优先级依据 —— 它们是平台自己不做、卖家又必须有人做的地方。

03能力缺口清单

按「外部证据强度 × 业务价值 × 与现有架构的贴合度」分级。每条都给了外部依据，避免凭感觉判断。

P0 — 建议优先补（外部对标明确缺失，且能直接讲成业务故事）

1. FBA 费用与货损索赔闭环 P0财务 / 物流

我们现在有「签收差异看板」，能发现少收 —— 但发现了之后没有下一步：没有费用试算与实际扣费的比对、没有丢货/损坏索赔、没有尺寸重测索赔、没有索赔状态跟踪与追回入账。整个「向亚马逊要钱」的闭环是断的。

外部依据：行业分析明确指出，FBA 费用索赔是亚马逊原生 AI 完全不覆盖、必须靠付费工具解决的 5 件事之一。存量业务里，这部分通常占销售额的 0.5%–2%，是纯增量利润。 来源：2026 亚马逊卖家 AI 工具覆盖度分析（cognitivefuture.ai）；领星「费用严控制」模块
涉及模块
amz-service-finance（主）+ amz-service-logistics（签收差异已有基础）+ 新增 SP-API Fees/Reimbursements 取数
关键动作
FBA 费用预估 vs 实际扣费差异比对 → 索赔候选生成 → 索赔单状态机 → 追回金额入账
业务价值
从「发现少收」升级为「把少收的钱要回来」，是可直接量化的利润改善

2. 财务结算与回款：补 SP-API Finances / Reports 取数 P0财务 / SP-API

财务模块只有 8 个端点（金蝶凭证同步、VAT、利润计算）。缺的是数据来源本身：FinancesClient、ReportsClient、FeesClient、PricingClient 在本项目中均不存在。

外部依据：领星的财务能力建立在「解析 10+ 张平台原表、提供 50+ 分析维度」之上，并强调订单级回款跟踪与先进先出成本核算。Reports API 与 Finances API 正是这些原表的来源 —— 没有它们，「真实单品利润」只能靠估算。 来源：领星 ERP 官方能力说明；本项目 SP-API 模块结构核查（SP-API 侧仅有 FbaInventory / Feeds / Orders）
涉及模块
amz-service-spapi（新增 Reports / Finances / Fees 客户端）+ amz-service-finance（结算明细、回款跟踪）
关键动作
Reports API 报表请求与轮询 → 结算原表落库 → 订单级回款台账 → 单品真实利润（含退款、仓储、广告）
与第 1 条关系
同属「向亚马逊要钱」冲刺包，取数层可复用

3. Agent 经验记忆闭环 + Supervisor-Worker 编排 P0AI / Agent

当前 Agent 是单 Agent ReAct + 29 工具。记忆只做了用户偏好与对话历史，没有「打法沉淀」。经核查：AgentMemoryController 提供的是偏好读写、历史查询、语言切换、提醒扫描；没有经验打分、成功率统计、低效经验停用。

另一个需要正视的点：代码中 supervisor/worker/orchestrat 唯一命中处，是 AgentChatStreamService 里一个名为 workers 的线程池，不是多 Agent 编排。

外部依据：WangM-A3/amazon-ops-agents 把 v2.2 的核心卖点直接放在「经验记忆闭环」上 —— 沉淀打法 → 同类任务自动注入 prompt → 打分回写 → 低成功率经验自动停用，主打「越用越懂这家店」。这是开源生态里公认的 Agent 差异化点，而非工具数量。 来源：GitHub WangM-A3/amazon-ops-agents README（v2.2 核心特性表）
涉及模块
amz-service-ai：agent/ 新增经验库与打分回写；MemoryAwareAgentService 扩展注入逻辑
关键动作
任务类型识别 → 经验检索注入 → 执行结果打分 → 成功率低于阈值自动停用 → 可选：Supervisor 拆分任务给多个专职 Worker
业务价值
Agent 从「每次重新想」变成「越用越准」；同时补齐面试口径中的 Supervisor-Worker（见第 05 节提醒）

4. Rufus / AI-SEO 适配度诊断 P0Listing / AI

我们的 Listing 健康度检查仍是「关键词 + 标题 + 五点 + 图片 + 搜索词」的传统 A9 口径。但买家的入口已经换人了：现在读你 Listing 的是 Rufus，它按「这个产品能不能回答这位买家的提问」来决定推不推荐。

外部依据：Rufus 已更名 Alexa for Shopping，覆盖约 3 亿客户、带来约 120 亿美元下游交易、使用量同比 +400%；同一关键词对不同买家返回不同结果，变化来自对话中透露的生活细节。亚马逊官方给卖家的动作建议已变成：标题写「使用情境」、主动回答买家会问的问题、完善 A+ 让 AI 有素材可学。 来源：亚马逊官方 AI 工具指南（gs.amazon.com.tw/ai-tools）；Q4 2025 财报电话会与 Rufus 新功能分析
涉及模块
amz-service-product（Listing 健康度扩展）+ amz-service-ai（用 LLM 生成诊断）
关键动作
新增「AI 推荐适配分」：使用情境覆盖度、Q&A 盲区、结构化规格完整度、A+ 素材充分度、评论可引用度
业务价值
把「Listing 优化」从关键词堆砌升级为「让 AI 愿意推荐你」—— 这是 2026 年最有说服力的一个故事

P1 — 值得补（成熟 ERP 都有，我们部分覆盖或空缺）

5. 商品侧自动调价与 Buy Box 抢位 P1

BuyBox 模块只做监控（BuyBox 实体 + Mapper + 竞品价格监控工具），没有动作。广告侧有分时调价与自动规则，但商品价格侧的自动调价（Repricing）在项目中检索为零命中。

外部依据：领星提供「定价利润试算」等运营工具；claudesdk 项目有独立的 repricing 策略技能。来源：领星运营工具清单；GitHub claudesdk-amazon-skills-chat 技能表

6. 品牌分析（ABA）与关键词调研深度 P1

关键词能力集中在广告模块的搜索词（15 端点）与 Listing 监控的关键词排名。缺 ABA 品牌分析口径（搜索频率排名、点击份额、转化份额）。

外部依据：sorftime 项目把关键词调研做成「1500+ 词库 + 8 维智能分类 + 广告策略输出（否定词/精准组/广泛组）」，粒度远超我们。来源：GitHub amazon-sorftime-research-MCP-skill README

7. 风险预警模型扩充 P1

独立预警实体仅两个：HijackAlert（跟卖）、NegativeReviewAlert（差评）。领星口径是 25–29 个模型，覆盖库存、库龄、Listing、店铺、财务。

外部依据：领星风险全维管理「25+ / 29+ 预警模型」；我们物流侧的看板已经验证了「分级 severity + 可执行清单」这套范式，可平移到其他域。来源：领星 ERP 官方介绍

8. AI 内容合规与 AIGC 披露 P1

AI 生成内容（文案、图片、素材）的合规披露在本项目为零覆盖。

外部依据：WangM 项目把「亚马逊 AI 人物图元数据披露 + 短视频 AIGC 标注」列为 v2.1 独立能力，属于双平台新规要求。来源：GitHub WangM-A3/amazon-ops-agents README

9. A+ 内容与变体（父子 ASIN）管理 P1

Listing 侧有健康度、变更日志、跨站复制，但无 A+ 内容管理与变体结构管理（variation / parent_asin 检索为零命中）。

外部依据：亚马逊原生 AI 已支持 A+ 生成与内容质量分析（从可读性、完整性、视觉、转化四维诊断，质量差会被前端折叠）；Rufus 推荐也依赖 A+ 素材。来源：亚马逊官方 AI 工具指南

10. 关税与到岸成本（Landed Cost） P1

无关税/进口环节成本核算能力，多平台与跨境场景下利润会失真。

外部依据：nexscope 与 claudesdk 两个项目都把 tariff calculator / 到岸成本列为独立技能。来源：GitHub nexscope-ai/Amazon-Skills、claudesdk-amazon-skills-chat

P2 — 锦上添花（生态趋势，但对当前重心不关键）

11. MCP Server 能力出口 P2

项目内 MCP 零覆盖。已有 29 个工具 + 约 330 端点，封装成 MCP 后能力可被任意 Agent 宿主复用。注意：若目标只是本项目自有 Agent，收益有限；若想体现「能力中台」定位，价值立刻上升。

12. 移动端与消息触达 P2

已有 IM 推送与每日报表调度，属半覆盖。领星的差异点是 APP / 小程序 + 微信每日业绩报告。

13. 浏览器自动化取数兜底 P2

多个开源项目用 Playwright 抓取 API 拿不到的数据（竞品评论、站内排名等）。可作为 SP-API 之外的第二取数通道，与我们已有的「外部导入 + 第三方 API」双入口思路一致。

04建议的三个冲刺包

不打散做。按「共同取数层 / 共同架构改动」归并，每个包内部有复用，做完就能讲成一个完整故事。

A · 「向亚马逊要钱」包

覆盖 P0-1 + P0-2 —— 财务与索赔，外部证据最强，且是平台自己不做的事
  1. 补 SP-API 取数层：新增 Reports / Finances / Fees 客户端，复用已有的 SigV4 签名、LWA Token、限流器与重试熔断。
  2. 结算原表落库：报表请求与轮询 → 解析 → 订单级回款台账。
  3. 费用差异比对：FBA 预估费用 vs 实际扣费，识别多收、尺寸重测、丢货与损坏。
  4. 索赔单闭环：候选生成 → 索赔状态机 → 追回金额入账（与物流签收差异看板打通）。
  5. 真实单品利润：把退款、仓储、广告、索赔追回统一计入，替换当前估算口径。
「我做的事一句话讲：帮卖家把亚马逊少给的钱找回来。以前只能看到『少了』，现在能看到少在哪、该不该赔、赔到了没。」

B · 「Agent 变聪明」包

覆盖 P0-3 + P0-4 —— 直接强化 AI Agent 主线，且顺手补齐面试口径
  1. 经验库落地：按任务类型存「打法」（推荐策略、成功参数、适用条件），执行后打分回写。
  2. 自动注入与淘汰：同类任务检索经验注入 prompt；成功率低于阈值自动停用。
  3. Supervisor-Worker 编排：引入 Supervisor 做任务拆分与结果聚合，工具按域下发给专职 Worker（已有 29 工具可按财务/广告/物流/选品自然分组）。
  4. AI 推荐适配分：在 Listing 健康度上加 Rufus 视角诊断 —— 使用情境、Q&A 盲区、结构化规格、A+ 充分度。
  5. 评估对齐：把经验生效前后纳入已有的 agent/eval 双轨评分，用数字证明「越用越准」。
「这个 Agent 的记忆不是聊天记录，是打法。同一个任务第二遍做，它用的策略比第一遍好，而且好多少我有评分记录。」

C · 「运营自动化」包

覆盖 P1-5 ～ P1-10 —— 把已有的监控能力接上动作，密度高、见效快
  1. 自动调价：把 BuyBox 监控接上价格动作，含护栏（最低毛利、单日调价次数上限）。
  2. 预警模型扩充：把物流看板已验证的「分级 severity + 可执行清单」范式平移到库存、库龄、Listing、财务。
  3. 合规检查：AI 生成内容的披露与标注检查，接入发布前卡点。
  4. A+ 与变体：A+ 内容质量诊断 + 父子 ASIN 变体结构管理。
  5. 关税与到岸成本：补齐跨境利润口径。
「系统从『告诉我出问题了』变成『帮我处理掉了』，而且每一步都有护栏和审计。」

05两个提醒

提醒一：一个口径风险，建议尽快处理。 面试口径里提到 Supervisor-Worker，但本项目代码中并未实现多 Agent 编排 —— 唯一命中的是一个名为 workers 的线程池。这是很容易被追问到、且一问就穿的表述。两条路选一条：要么在冲刺包 B 里真正补上 Supervisor-Worker（推荐，因为经验记忆本来就需要编排配合）；要么把口径改成「单 Agent ReAct + 29 工具 + 工具级权限治理」，并把 Supervisor-Worker 明确划到另一项目（智云）去讲。含糊放着是风险最高的一种处理。
提醒二：有 5 件事不必做，因为亚马逊已经免费做了。 Listing 与 A+ 的文案生成、AI 素材（图/视频/音频）生成、基础关键词建议 —— 这些做出来是重复造轮子，且质量比不过平台原生工具。补能力的判断标准应该是：这件事亚马逊原生 AI 会不会做？会做的就别做，把力气放在它不做的 5 件事上 —— PPC 调优、品牌与跟卖预警、选品研判、真实单品利润、FBA 索赔。本报告的 P0 正是按这个标准选出来的。
