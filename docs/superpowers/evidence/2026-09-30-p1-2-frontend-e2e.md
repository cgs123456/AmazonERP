# P1-2 前端 E2E：hermetic 化 + 接入 CI（2026-09-30）

> 结论先行：P1-2 已闭环。旧 E2E 实测基线 23 passed / 16 failed / 10.3 分钟，且**从未被 CI 执行过**；
> 本轮改为 hermetic 打桩后本地 45/45、远端 ubuntu-latest 45/45（run `36641126754`），并已在 ci.yml 中守护。
> 顺带修掉一个真实的前端崩溃（Dashboard 在后端返回非数组时白屏）。

## 1. 起点：旧基线的实测数字（不是估计）

| 项 | 实测值 | 来源 |
|----|--------|------|
| 旧套件规模 | 39 个用例 | `npx playwright test` 全量 |
| 旧基线结果 | **23 passed / 16 failed** | 同上，跑两遍一致（10.1m / 10.3m） |
| 旧基线耗时 | 10.1 ~ 10.3 分钟 | 同上 |
| 16 个失败的性质 | **全部是超时**，不是产品缺陷 | 失败信息均为 `Test timeout` / `networkidle` 未达成 |
| 是否进 CI | **否** | ci.yml `frontend` job 只有 type-check / vitest / build |

关于「25/25 通过」的说法：源自 commit `471ee60`，**已过期**。它之所以能腐烂而不被发现，
就是因为没有任何一条 CI 流水线执行 `test:e2e`。本轮补的是这个洞。

## 2. 根因（两条叠加）

1. 套件自称「连接本地真实后端栈」，但本地与 CI runner 都没有 16 个微服务在跑，`/api/*` 必然失败。
2. 本地还叠加系统代理：失败请求**挂住**而不是快速失败，于是 `waitForLoadState('networkidle')` 永不达成。

冷启动 vite 又叠加了首屏编译耗时，所以表现为「大面积超时」而非「快速报错」。

## 3. 方案：hermetic 打桩，而不是起 16 个后端

- Docker 拉镜像在本机不可用（docker daemon 代理 `127.0.0.1:7897` 已死），CI 上也没有后端服务。
- 打桩后单套件秒级到 2 分钟量级，具备进 CI 的条件。
- 桩数据是固定常量，**不含时间戳/随机值**，结果可复现（延续 Phase 0 确定性原则）。

## 4. 两条「假通过」用例的修正（重要）

这两条在旧套件里是绿的，但实际上什么都没测到：

1. **`Dashboard 交互 › KPI 卡片与图表区域渲染`**：原断言 `.kpi-grid` / `.chart-card` 存在。
   但**骨架屏里也有同名节点**，所以「数据永远加载不出来」时它照样通过。
   → 改为：先断言 `.skeleton-zone` 消失，再断言 4 张 KPI 卡与真实数值（`$12345.67`、`23`、`12.5%`、`$536.77`）以及 7 根趋势柱。
2. **`Dashboard 交互 › Agent 发送消息应收到回复`**：原断言「回复非空」。
   而 `/api/ai/chat-stream` 若按 JSON 兜底返回，`fetch` 拿到 200 但 `readSseStream` 解析不出任何事件，
   占位气泡永远是空串——页面看起来没坏，但也没回复。
   → 桩改为按 SSE 帧协议返回 `final` 事件，断言回复包含 `23 笔订单` / `$12,345.67`。

同时给 fixture 加了全局防护：捕获 `pageerror`，用例结束时若存在未处理异常即失败。
没有这条时，把页面打进渲染异常的 bug 会被「页面标题非空」这类弱断言放过。

## 5. 修掉的真实前端崩溃（不是测试问题）

`/report/dashboard/sales-trend` 的返回值被 `Dashboard#maxSales` 用 `for...of` 遍历。
后端（或桩）返回非数组时抛 `TypeError: salesTrend.value is not iterable`，
Vue 渲染中断 → **骨架屏永不消失、页面等于白屏**。

- 修复：`Dashboard.vue` 三组数据赋值前加 `Array.isArray` 防御，非数组退到 mock。
- 这属于产品健壮性问题，与打桩无关：后端字段变更/异常分支返回非数组就会触发。

## 7. 诚实边界（后人不得误读）

1. **打桩 ≠ 后端契约验证。** 这套测试只证明「前端拿到这样的响应会这样渲染/交互」，
   不证明后端真的返回这个结构。后端改字段名而前端未同步时，CI 仍然会绿——
   那是后端集成测试的职责，本套件不覆盖。
2. **视觉/截图断言不可靠。** 桩对外部域一律 abort，图标 CDN 不加载，所以用例只依赖文本与 DOM。
3. **桩只装在 fixture `page` 上。** 自建 `browser.newContext()` 的 4 条用例（all-pages 3 条、
   full-interaction 1 条）不带桩；它们目前只 goto `/` 或依赖路由守卫，不依赖 API。
4. **仍有一批旧用例断言偏弱**（`content.length > 100`、"标题非空"等），本次未逐条重写。
   它们现在的价值主要来自 §4 的 pageerror 防护，而不是自身断言。逐条重写列为后续项。
5. **耗时成本**：E2E 让 `frontend` job 从约 1 分钟增加到约 3 分钟（含浏览器安装）。
   若后续觉得慢，可把浏览器安装换成缓存或 `mcr.microsoft.com/playwright` 镜像，但不要用 skip 换绿。
